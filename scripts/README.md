# VK Teams: проверенный прототип Sticker Studio

## Файлы

- `add-sticker.mjs` — вход через Workspace, создание Messenger-сессии,
  запросы к Stickers Bot и загрузка файла. Экспортирует функции для сервера;
  также запускается отдельно из терминала.
- `sticker-test-server.mjs` — локальный сервер прототипа для одного пользователя.
  Держит текущую VK Teams-сессию в памяти.
- `sticker-test.html` — тестовый интерфейс входа, выбора авторского пака,
  добавления стикера и создания нового пака.

Пробы `workspace-auth-probe.mjs` и `workspace-password-probe.mjs` удалены:
рабочая авторизация перенесена в `add-sticker.mjs`.

## Запуск

Из корня проекта:

```sh
node scripts/sticker-test-server.mjs
```

Открыть `http://127.0.0.1:4177/`. После одного входа можно отправлять несколько
стикеров, используя ту же серверную сессию.

Отдельный запуск из терминала:

```sh
node scripts/add-sticker.mjs --help
node scripts/add-sticker.mjs /path/to/sticker.webp https://files.myteam.mail.ru/get/EXISTING_STICKER_ID
```

Второй аргумент — ссылка на существующий стикер выбранного авторского пака.
Этот режим каждый раз выполняет новый вход и запрашивает пароль скрытым вводом.

## Подключение к редактору

Локальный редактор использует этот сервер как временный backend для Фазы 1.
Запустите в двух терминалах из корня проекта:

```sh
npm run dev:vk
npm run dev
```

Откройте адрес Vite, затем стикер в редакторе. Кнопка Export открывает панель
сохранения PNG, библиотеки и VK Workspace. Vite перенаправляет запросы
`/api/vk/*` на локальный сервер `127.0.0.1:4177`. Пароль не сохраняется;
сессия VK, cookies и `aimsid` остаются в Node.

Экспорт использует `exportStickerBlob()` из `packages/editor`. VK получает
PNG `Blob` напрямую в теле запроса. После перезапуска сервера нужен новый вход.

Результат отправки имеет `kind`: `confirmed`, `auth_required`, `retryable`
или `unknown`. При `unknown` изображение могло дойти до бота: проверьте пак
в VK перед новой отправкой. Автоматического повтора нет.

Если сервер не смог найти ссылку на существующий стикер выбранного пака,
временная форма попросит её вручную.

Кнопка Upload в VK Workspace берёт готовое изображение из экспорта
редактора как `Blob` и отправляет его на сервер Sticker Studio вместе с ID
выбранного пака. Сохранение изображения на диск пользователя не требуется.

Пользовательский сценарий:

1. При первом подключении к VK Teams пользователь вводит логин и пароль.
2. Сервер выполняет авторизацию; список авторских паков загружается отдельным запросом.
3. Пользователь выбирает пак и подтверждает отправку готового стикера.
4. Сервер выбирает пак у Stickers Bot, загружает файл и отправляет URL боту.
5. Интерфейс показывает подтверждение добавления; следующие отправки используют
   ту же сессию.

У прототипа уже есть следующие маршруты:

| Маршрут | Назначение |
| --- | --- |
| `GET /api/session` | Текущая in-memory сессия и список паков без VK-секретов |
| `POST /api/authorize` | Авторизация без запроса списка паков |
| `POST /api/prepare-pack` | Подготовка нового пака без отправки изображения |
| `POST /api/login` | Вход; JSON с `email`, `password` и необязательным кешем `ownedPacks` |
| `POST /api/upload` | Бинарный файл; заголовки `X-Pack-Id`, `X-File-Name` |
| `POST /api/refresh-packs` | Свежий список от бота, с сообщениями в его чат |
| `POST /api/check-name` | Проверка адреса нового пака |
| `POST /api/create-pack` | Создание пака с первым стикером |

`X-File-Name` кодируется через `encodeURIComponent`. Если сервер не смог получить
ссылку на существующий стикер пака, прототип запрашивает её у пользователя
и передаёт в `X-Sticker-Reference`.

Эти маршруты обслуживают тестовую страницу на `127.0.0.1:4177` и редактор
через прокси разработки Vite. `/api/session` возвращает список паков для
повторного открытия редактора без нового входа. Для production понадобятся
собственный backend, сессии пользователей и защищённое хранение VK-сессий.

## Сессии и ограничения прототипа

- В запросе `withSession` указано `sessionTimeout: 2592000` — 30 суток.
  Это запрошенный срок, не подтверждённая гарантия фактического срока cloud-сессии.
- Для действий используется `aimsid`. `silent_token` нужен для создания сессии;
  значение `access_token` сейчас не сохраняется для последующего использования.
- Пароль, VK cookies, токены и `aimsid` не записываются на диск и не выводятся.
  После перезапуска Node серверная сессия теряется.
- Browser cache содержит только ID и адреса авторских паков. Он не восстанавливает
  авторизацию. При загрузке страницы автоматическое восстановление интерфейса
  уже открытой серверной сессии пока не реализовано.
- Автоматическое продление или восстановление истёкшей VK-сессии не реализовано.
  Подтверждённого refresh-запроса в исследованной цепочке нет.
- Сервер использует одну глобальную сессию и блокировку; авторизация использует
  общий cookie jar. Для нескольких пользователей нужны отдельные состояния,
  cookie jar и очередь операций для каждого пользователя.
- При интеграции браузер должен получать только сессию самого Sticker Studio;
  VK `aimsid` и токены остаются на backend. Сессию VK нужно проверять до отправки;
  при отказе авторизации снова показывать подключение VK Teams.
- Если файл уже отправлен боту, нельзя автоматически повторять отправку после
  неоднозначного ответа: это может добавить дубликат.

Для сохранения подключения после перезапуска backend потребовалось бы отдельное
решение для защищённого хранения VK-сессий. Сейчас такое хранение не реализовано.
